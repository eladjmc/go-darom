# Go Darom — UX & Visual Design Baseline

**Version:** 0.1  
**Status:** DRAFT — requires owner design review  
**Source of truth:** Approved Product Baseline v0.1 and System HLD v0.2. This pack does not change game rules or scope.

## Contents and reading order
1. `INFORMATION_ARCHITECTURE.md` — routes, access, navigation, and global shells.
2. `DESIGN_SYSTEM.md` — visual tokens, layout, components, typography and imagery.
3. `SCREEN_SPECIFICATIONS.md` — screen-by-screen purpose, actions and states.
4. `USER_FLOWS_AND_STATES.md` — UX sequences and their exceptional paths.
5. `MOTION_AND_ACCESSIBILITY.md` — motion, behavior, input/accessibility.
6. `VISUAL_REFERENCES.md` — image references and what is / is not normative.
7. `DESIGN_REVIEW.md` — open design choices and sign-off criteria.

## Intent
- Warm, sophisticated Hebrew RTL community UI; understated Japanese Go cues rather than theme-park decoration.
- Conventional, board-first game room UX inspired by OGS, without cloning its copyrighted visual expression or features.
- All documented MVP modules are covered. No ELO, rankings, competitive tournaments or automated matchmaking.
- Frontend implementation is React + Vite, within approved HLD. This document is a UX specification, **not** implementation code or an approved UI component library.

## Approval boundary
- Approved product decisions are normative. Visual tokens and specific layout measurements below are **design proposals** pending approval.
- Imagery and invented text in generated reference images are illustrative; do not treat fictional dates, scores, tourneys, stats, profiles or marketing features as requirements.
- Open questions are tracked in `DESIGN_REVIEW.md` and inherited product open issues.
